> 一体机注册中心设计的需求变更，按批次累积。设计以同目录[设计文档](./一体机Agent%20OS%20registry设计文档.md)、[OpenAPI 契约](./registry_openapi.yaml)为准，落地进度见[开发进展](./开发进展.md)。

## 1. 鉴权 → mTLS（已实现）

注册中心不再用自带鉴权（静态 API Key / token）。内部组件（gateway / 管理面 / 镜像处理模块）与注册中心之间用 **mTLS 双向认证**：配置内部 CA 签发的证书即启用，未配则纯 http；由传输层校验组件身份**替代业务层鉴权**。

- **影响**：移除 auth 门控设计；[§3.3.4 安全](./一体机Agent%20OS%20registry设计文档.md#334-端口与安全)改 mTLS；**无端点 / 参数变化**。
- **状态**：**已实现**（backend `uvicorn ssl_*` + `agent-gateway` `module.sh`，配了 `A2X_REGISTRY_TLS_CERTFILE/KEYFILE/CA_CERTS` 即 mTLS）。

## 2. 存活监控：注册中心不收心跳，改 gateway 轮询元戎（待实现）

注册中心**不再接收心跳、不派生状态**。gateway 周期轮询**元戎 List 接口**（[yuanrong#358](https://gitcode.com/openeuler/yuanrong/issues/358)）拿"当前在运行的实例"，把不在运行的经 `PATCH` 置 `停止` / `异常`。

- **影响**：移除 `heartbeat/` 模块与 `POST /api/nodes/{node}/heartbeat`、`GET/POST /api/lease-config`；`status` 改由 gateway 写。
- **状态**：**待实现**（当前心跳模块仍在、默认关闭）。

## 3. status 落库可改 + 用户面 Agent 条目（待实现）

- `status` 成**落库可改字段**（`运行` / `停止` / `异常`，中文），由 gateway 写，注册中心**不派生、不自动剔除**。
- 用户面看到 **Agent 条目**：每用户每框架 ≤ 1 个、**不随实例停止消失**、由**用户手动删除**；用户面与管理面**共用同一实例注册表**。
- **影响**：`instance` 表加 `status` 列；`PATCH` 加 `status`；实例删除发起方由 gateway 改为**用户**。`GET /api/instances` **保留 `include_unhealthy`**（默认只回 `运行`，"非运行"由原 `异常` 扩为 `停止` + `异常`）——**管理面接口不变**。
- **状态**：**待实现**（当前 `status` 查询派生、`PATCH` 只 `node` / `address`）。

## 4. ETCD 兼容（待实现）

rqlite 与 etcd **双支持**（依赖倒置抽象为 8 个表操作原语），etcd 复用元戎在一体机提供的 etcd、仅一体机可选；**两后端行为一致**（含分页 / 筛选，无 `NotImplementedError`），组合逻辑收在 service 层。详见 [`ETCD兼容分析.md`](./ETCD兼容分析.md)。

- **状态**：**待实现**（方案与工作量见 [`ETCD兼容分析.md`](./ETCD兼容分析.md)，约 385–575 行；未开工）。

## 5. 实例注册表新增 `instance_id` 字段（保存元戎实例 ID）（待实现）

实例注册表新增 **`instance_id`** 字段，用于保存**元戎为该实例分配的实例 ID**。gateway 经元戎拉起实例后，元戎返回其实例标识，gateway 注册 / 变更实例时一并带上，注册中心落库保存。

- **用途**：把注册中心的实例条目与元戎侧实例一一对应——gateway 轮询元戎 List（[§2](#2-存活监控注册中心不收心跳改-gateway-轮询元戎待实现)）比对存活、或按元戎实例 ID 停止 / 定位时的关联键。
- **与 `service_id` 的区别**：`service_id` 是注册中心主键（user+framework 派生、幂等）；`instance_id` 是**元戎侧**的实例标识，二者独立，`instance_id` 不做主键、可为空（非元戎拉起或尚未回填时）。
- **影响**：`instance` 表加 `instance_id` 列；`POST /api/instances` 请求体、`InstanceEntry` 响应加 `instance_id`；`PATCH /api/instances/{service_id}` 允许更新 `instance_id`（元戎迁移后实例 ID 变化时回填）。**管理面 / 用户面查询接口路径不变**。
- **状态**：**待实现**（当前实例表无此列，注册体仅 `service_id/kind/framework/framework_version/node/address/user`）。

## 6. 镜像注册表以 `name` 为主键（`framework` 降级 + 字段重构）（待实现）

镜像注册表主键由 `framework` 改为 **`name`**，`framework` 降级为普通展示字段，并重构 / 新增若干字段。

**主键与默认版本**
- **`name` 作为主键**：镜像注册表以 `name` 标识一类镜像（取代原先 `framework` 的定位作用）。
- **`framework` 降级**：仅作展示用普通字段，不再参与主键 / 默认版本 / 检索定位；其过去功能全部由 `name` 替代。
- **默认版本按 `name`**：同一 `name` 下**有且只有一个**默认版本（与 `framework` 无关）。

**字段变更**
- **`framework_version` 更名为 `version`**（`framework_version` 过渡期保留、标记待删除）。
- **新增三个纯文本字段**：`description`（描述）、`package_path`（包路径）、`image_archive_path`（镜像归档路径）。
- **新增 `access_mode` 数组**：每项 `{ name, port, cmd }`，声明该镜像的一种接入方式（如 tui / web），供拉起 / 接入时选用。

**接口路径变更**（`{framework}` → `{name}`）
| 原 | 新 |
|---|---|
| `PUT /api/images/{framework}/default` 设默认版本 | `PUT /api/images/{name}/default` |
| `GET /api/images/{framework}/launch-spec` 取默认 / 指定版本运行规格（Switch 用） | `GET /api/images/{name}/launch-spec` |

**镜像注册元数据示例**
```jsonc
{
  "framework": "openclaw",              // 降级为普通展示字段
  "name": "openclaw",                   // 新主键
  "description": "xxxxxxxx",            // 新增
  "package_path": "/xxx/xxx/",          // 新增
  "image_archive_path": "/xxx/xxx/",    // 新增
  "framework_version": "v0.2.0",        // 待删除（由 version 取代）
  "version": "v0.2.0",                  // framework_version 更名
  "runtime_spec": {
    "imageurl": "harbor.local/adapted/openclaw:v0.2.0-mod1.3",
    "cpu": 1000,
    "memory": 2048
  },
  "access_mode": [                      // 新增：接入方式数组
    { "name": "tui", "port": "2222",  "cmd": "openclaw" },
    { "name": "web", "port": "18789", "cmd": "openclaw gateway --port 18789" }
  ],
  "env_vars": { "A2X_LLM_KEY": "${A2X_LLM_KEY}" },
  "workspace": "/app",
  "mounts": [ { "source": "/data/agent", "target": "/data", "readonly": false } ],
  "image_module_version": "v1.3",
  "uploaded_by": "user-01"
}
```

- **影响**：镜像注册表主键改 `name`；`RegisterImageRequest` / `ImageEntry` / `LaunchSpec` / `ImageOpResponse` 增删字段；两个 `{framework}` 路径改 `{name}`；查询 / 排序 / 默认版本逻辑由 `framework` 维度改 `name` 维度。
- **状态**：**待实现**（本批只记录需求，OpenAPI 与实现改造后续进行）。

## 7. 实例 POST/DELETE 双模式 + registry 直连元戎（待实现）

实例的**创建 / 删除**接口支持**两种模式**：
- **A. 仅条目**（**向前兼容**，后续可能移除）：只在注册表创建 / 删除条目，不碰元戎——元戎实例由调用方（gateway）自己拉起 / 停止。
- **B. 同步元戎**（新默认）：注册中心**自己调元戎接口**创建 / 删除实例，**元戎成功后再**建 / 删条目，然后才回响应。

**流程变更**（模式 B）：

| | 现状（gateway 调元戎） | 改后（registry 调元戎） |
|---|---|---|
| 创建 | gateway 取规格 → **gateway** 调元戎 create → gateway 调 registry 注册条目 | gateway 取规格 → gateway 调 registry「创建+注册」→ **registry** 调元戎 create → 建条目 |
| 删除 | gateway 调元戎 delete → gateway 调 registry 删条目 | gateway 调 registry「删除」→ **registry** 调元戎 delete → 删条目 |

**registry = 哑转发 + 记录**（不持有 builtin 规格、不分 agent 类型）：
- 元戎 `create_sandbox` 与 agent 类型**无关**（只收 `runtime_spec` 原样转发；三方/九问的分叉发生在 gateway 组装规格那一步）。故 registry **不持有九问 builtin 规格、不按类型分支**，两类走同一条「转发+记录」路径，**所需规格全部来自模式 B 入参**（gateway 组装好传入）。
- **模式 B 入参 = 元戎 create payload（`namespace`/`name`/`workspace`/`runtime_spec`/`env_vars`/`mounts`）+ `version`**（`version` 为注册中心专属，注销镜像「查在用实例」要用）。
- 自动补足：`service_id`/`user`/`framework` ← 拆 `name`；`node`/`address`/`instance_id` ← 元戎返回回填；`kind` ← registry 按 `name == "jiuwenswarm"`（jiuwenswarm `BUILTIN_AGENT_TYPE`）判 `九问`、否则 `三方`，**无需 gateway 传**。

**模式判定 = 看入参形状**（不设开关字段）：
- 带 `runtime_spec` → **模式 B**；无 `runtime_spec`、带 `node`/`address` → **模式 A**。
- 兜底校验：有元戎类字段却缺 `runtime_spec` → `400`；两者都无 → `400`；同时给 `runtime_spec` 与 `node`/`address` → **以 B 为准**（落点由元戎返回覆盖）。
- 模式 A 退役后，请求恒带 `runtime_spec`、判据恒为 B，不留历史包袱。

**DELETE 接口形状**（与 POST 对称：看形状判模式，无独立开关）：
```
DELETE /api/instances/{service_id}[?with_runtime=true]
  {service_id} = 具体 id → 删一个；= ALL → 删全部（暂不提供过滤）
  无 with_runtime   → 模式 A：只删条目（向前兼容）
  with_runtime=true → 模式 B：先按条目 instance_id 调元戎 delete_sandbox，成功后删条目
```
- **批量 = `ALL`**（删全部，暂不提供过滤；不设 body 列表端点）；模式 B 的 ALL 对每个条目**并发**调元戎 delete（`asyncio.gather` 限流）→ 逐条删条目，**逐条报结果、部分失败不回滚**。
- **幂等**：条目本不存在 → `deleted:false`；元戎已无该实例 → 视作成功继续删条目。
- 响应：单个 `{service_id, deleted, runtime_deleted?}`；ALL/多个 `{total, deleted, results:[{service_id, deleted, error?}]}`。
- **异步不阻塞**：元戎 create / delete **返回需要时间**（已调研，元戎 `/api/agent` 默认超时 300s）；等待期间**不能阻塞**事件循环，须走**协程**（元戎阻塞 HTTP 包进 `asyncio.to_thread`）。**元戎成功响应后**才建 / 删条目，**再**回 gateway。
- **并发互斥**：同一 `service_id` 同一时刻只允许一个在途操作——创建 / 删除进行中，其间到达的**同 `service_id` 创建或删除请求一律拒绝 `409 in_progress`**（in-flight 锁按 `service_id`，含获取锁的等待上限，超时亦 `409`）。

**落地细节（已敲定）**：
- **顺序与补偿**：严格「元戎成功 → 再增 / 删条目」。若元戎已成功、条目增 / 删**失败 → 重试 N 次**；仍失败则**报错 + 记日志**（不做反向补偿删除；孤儿实例 / 僵尸条目留日志待对账）。
- **重复创建幂等**：模式 B 创建前先查条目；**已存在且实例存活 → 直接回现有条目，不二次拉起元戎**。
- **`name` 解析**：`service_id = "user+framework"` 按**首个 `+`** 拆——左为 `user`、右为 `framework`（`user` 不得含 `+`）；`kind` 由 `framework == "jiuwenswarm"` 判。
- **落点回填**：元戎 `create_sandbox` 只回 `instance_id`；创建后**再调 `get_agent_info` 取全部落点信息（node_ip / sandbox_ip 等），拿齐后才写条目**。
- **`version` 必填（模式 B）**：缺 → `400`（注销镜像的在用校验要用）。
- **元戎未配置**：模式 B 请求但未配元戎连接 → `501 runtime_not_configured`。
- **namespace**：以 registry 自身配置为准（不信任入参覆盖）。
- **超时协同**：gateway→registry 的 HTTP 超时须 **> 300s**（registry 等元戎的上限），否则 gateway 先断。
- **错误码**：`409 in_progress` / `501 runtime_not_configured` / `502 yuanrong_failed` / `504`（元戎超时）；批量部分失败 → `200` + 逐条 `results`。
- **元戎客户端依赖**：与 gateway 同款——**`urllib`（stdlib，零新依赖）**（gateway `YuanrongFrontendAgentClient` 即用 urllib，也与我们 rqlite/etcd 客户端一致）。
- **`ALL` 不加 confirm**。

- **可复用**：jiuwenswarm `YuanrongFrontendAgentClient.create_sandbox` / `delete_sandbox`（`POST` / `DELETE /api/agent`）、`get_or_create_agent(key, creator=…)` 的同 key 并发去重模式（见 §调研）。
- **`service_id` 与元戎 `name` 同源**：`service_id` 由 `instance_sid` 的哈希改为直接 `"{user}+{framework}"`（如 `user-01+opencode`），**恰等于元戎 `POST /api/agent` 的 `name`**。故模式 B 里 `name(元戎) = service_id(注册中心)`，无需再单独拼 name；in-flight 锁 key、条目主键、元戎实例标识三者同源。
- **状态**：**待实现**（本批记录需求 + 接口 / 实现方案，落地后续进行）。
