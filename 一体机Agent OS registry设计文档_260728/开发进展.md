## 1. 已实现

### 1.1 镜像管理（完整）

| 能力 | 接口 | 说明 |
|------|------|------|
| 镜像注册 | `POST /api/images` | `runtime_spec` 不透明 JSON 透传；`env_vars` / `workspace` / `mounts` / `image_module_version` 顶层字段；按 `image_sid(framework, version)` 幂等 upsert；框架首个版本自动置为默认 |
| 镜像查询 | `GET /api/images` | 扁平行返回；`framework` / `uploaded_by` 筛选；`size` / `page` 分页 + `X-Total-Count` / `X-Page` / `X-Total-Pages` / `X-Page-Size` 响应头；SQL 侧 `LIMIT/OFFSET` |
| 取运行规格 | `GET /api/images/{framework}/launch-spec` | 不带 `version` 取默认版本；无默认时回退到 `version_key` 最大的一版 |
| 设默认版本 | `PUT /api/images/{framework}/default` | 旧默认清零 + 新默认置一 |
| 镜像注销 | `DELETE /api/images/{framework}/{version}` | 先查实例注册表校验无在用，有则 `409`；删掉默认版本后自动提升剩余最新版为默认 |

`version_key` 规范化排序键（注册时算好落库）与确定序 `framework ASC, version_key DESC, json_extract(data,'$.created_at') DESC` 均已实现。

### 1.2 实例管理（完整）

| 能力 | 接口 | 说明 |
|------|------|------|
| 实例注册 | `POST /api/instances` | 七个必填字段校验；`kind` 限 `三方` / `九问`；`service_id` 幂等 upsert，`created_at` 保留首次值 |
| 实例变更 | `PATCH /api/instances/{service_id}` | `node` / `address` 至少给一个；`address` 合并进 `data` JSON |
| 实例注销 | `DELETE /api/instances/{service_id}` | 幂等，返回 `deleted` 布尔 |
| 实例查询 | `GET /api/instances` | `node` / `framework` / `kind` / `user` 筛选；分页 + 响应头；确定序 `framework ASC, "user" ASC, service_id ASC`；`include_unhealthy=false` 下推成 SQL 的 `node NOT IN (…)`，使计数与翻页都在库内完成 |

### 1.3 存储（rqlite）

- `common/db.py` 提供统一 `Backend` 抽象，`connect(cfg)` 支持 `rqlite` / `sqlite` / `memory` 三种后端，业务代码不感知 kind。
- `RqliteConnection` 用标准库 `urllib` 直连 rqlite HTTP API（`POST /db/execute`、`POST /db/query?associative&str`），**无第三方依赖**；支持 Basic 认证（`A2X_REGISTRY_DB_AUTH`）。
- 建表 SQL 为单一真源（`SCHEMA_SQL`），全部 `CREATE ... IF NOT EXISTS`；rqlite 路径会剥掉行注释后逐句执行（rqlite HTTP API 不接受多语句脚本）。
- `A2X_REGISTRY_MODE=appliance` 时启动建 `images` / `instances` 两个命名注册表；非 appliance 时镜像 / 实例路由返回 `404`。
- 多节点 rqlite 已有测试覆盖：`tests/start_rqlite_cluster.sh`（docker compose 起 3 节点、等选主、校验 `/nodes`）+ `tests/db/test_crud_rqlite.py` / `test_image_rqlite.py` / `test_instance_rqlite.py` / `test_schema_rqlite.py`。
- 测试文档：`docs/testing/rqlite_test.md`（rqlite 部署与验证步骤）、`docs/testing/curl_test_cases.md`（全接口 curl 用例）。

### 1.4 启动配置（环境变量形态）

`backend/__main__.py` 的 `parse_runtime_config()` 已支持：`A2X_REGISTRY_MODE`（限 `""` / `appliance`）、`A2X_REGISTRY_BIND`（空 → `127.0.0.1`，**显式拒绝 `0.0.0.0`**）、`A2X_REGISTRY_PORT`、`A2X_REGISTRY_DB_KIND`；`backend/startup.py` 另读 `A2X_REGISTRY_DB_ENDPOINT` / `A2X_REGISTRY_DB_AUTH`。CLI 已按设计**不提供 `--host`**。

### 1.5 agentos 接入（单机）

- `deploy/agentos.sh` 的 `MODULES` 已含 `agent-gateway`，顺序 `jiuwenbox → yuanrong → agent-gateway → jiuwenswarm`。
- `deploy/agent-gateway/module.sh` 四个钩子齐备：`install`（装 rqlite rpm + pip 装 whl + heredoc 生成 `agent-registry.service`）、`up`（算 BIND → 写 systemd drop-in → `systemctl enable --now rqlited agent-registry` → curl 健康检查 15 次重试）、`down`、`uninstall`。
- `build/build.sh` 的 `build_agent_gateway()` 已下载注册中心 whl 与 rqlite rpm 并打进 `AgentOS-Server-<arch>.tgz`。

## 2. 开发中

### 2.1 节点级心跳保活（存活监控）

**状态：开发中，B020 不交付。**

服务端已具备：

| 件 | 位置 |
|---|---|
| 接口 | `POST /api/nodes/{node}/heartbeat`、`GET/POST /api/lease-config`（`heartbeat/router.py`）|
| 租约表 | `NodeHeartbeatStore`（key = nodeIP），复用通用 `LeaseTable` 状态机 |
| 管理器 | `HeartbeatManager.heartbeat / is_expired / expired_nodes / sweep_once` |
| 清理 | `NodeHeartbeatSweeper`，5s 一跳，超宽限调 `InstanceService.expire_node` |
| 装配 | appliance 模式启动时自动拉起，并注入 `InstanceService` 用于派生 `运行` / `异常` |
| 测试 | `tests/heartbeat/test_node_*.py`、`tests/backend/test_startup_node_heartbeat.py` |

**默认关闭**：`NodeLeaseConfig.enabled = False`（`heartbeat/models.py`），且 `recover_from_persisted()` 见到 `enabled=False` 直接返回（`heartbeat/store.py`）。此时 `POST /api/nodes/{node}/heartbeat` 返回 `400`，租约表恒为空、扫描线程空转，`status` 一律派生为 `运行`，实例只由 gateway 显式注销来删除。运维经 `POST /api/lease-config` 打开。

**尚缺两项**：

1. **gateway 不发心跳** —— 接口有，无调用方，端到端未打通。
2. **客户端 SDK 未封装** —— `client/a2x_registry_client/` 无 `/api/nodes` 方法（`/api/images`、`/api/instances` 同样没有，见 [§3.9](#39-客户端-sdk-一体机接口封装)），gateway 只能自己拼 HTTP。

**打开开关后的两个已知细节**（优先级低）：

- `LeaseTable.sweep_tick()` 不检查 `enabled`。由开改回关时**已装载的租约不被撤销**，扫描线程仍会在 TTL + 宽限后删掉那些 node 的实例；关开关需一并清空租约表。
- 运行期打开时，启动阶段的 `recover_from_persisted()` 已跳过，既有 node 在首个心跳到达前无租约、恒判健康（fail-open，不误删）。

## 3. 未实现

### 3.1 `registry.env` 配置文件

代码**没有任何读配置文件的逻辑**，`parse_runtime_config()` 只读进程环境变量；`backend/__main__.py` 的 docstring 里那句 "comes from `registry.env`" 描述的是部署约定，不是代码行为。

当前 agent-os 的实际做法是 `up` 钩子生成 systemd drop-in：

```ini
# /etc/systemd/system/agent-registry.service.d/env.conf
[Service]
Environment=A2X_REGISTRY_BIND=<网卡IP>
Environment=A2X_REGISTRY_PORT=4003
Environment=A2X_REGISTRY_MODE=appliance
Environment=A2X_REGISTRY_DB_KIND=rqlite
Environment=A2X_REGISTRY_DB_ENDPOINT=http://127.0.0.1:4001
```

**待做**：改为 `EnvironmentFile=/etc/a2x-registry/registry.env` + systemd `ConditionPathExists` 据其存在与否决定是否起服务；`module.sh` 的 `up` / `uninstall` 相应改为写 / 删该文件。

> 仓根的 `AgentRegistry/registry.env` **不是**这个文件：它用 `export VAR=…` 的 shell 语法，`A2X_REGISTRY_DB_KIND=memory`、`A2X_REGISTRY_HOME` 指向本地测试目录，供开发自测 `source`（见 `docs/testing/curl_test_cases.md`）。systemd 的 `EnvironmentFile=` 不接受 `export` 前缀，故它不能充当部署配置。

### 3.2 服务注册表未进 rqlite

`SCHEMA_SQL` 里建了 `service` 表，但通用服务的 CRUD（`GET/POST /api/datasets/{dataset}/services` 一系列接口）走的**仍是文件**：`register/store.py` 的 `RegistryStore` 读写 `user_config.json` / `api_config.json` / `service.json`，与 `RegistryTableService`（SQL 路径）完全并行、互不相通。

只有镜像与实例两张表真正落 rqlite。**后果**：多机形态下服务注册表不会跨节点共享，主备切换后服务数据不一致。

### 3.3 注册中心主备（跟随 rqlite Raft 选主）

**完全未实现**。代码里没有任何：查本机 rqlite 的 Raft 状态、判断自己是否 leader、角色切换、备节点停扫描、备节点健康检查返 `503` 的逻辑。当前每个启动起来的注册中心实例都认为自己在正常服务。

### 3.4 nginx 入口与 upstream 改写

**完全未实现**，代码与部署脚本里都没有 nginx 相关内容。当前 gateway 直连注册中心的 `4003`。

### 3.5 HA 接口

`GET /api/ha/leader`、`GET/POST /api/ha/members` —— **路由不存在**。（`a2x_registry/cluster/` 下的 `/api/cluster/*` 是 A2X 通用注册中心的跨实例 gossip 同步，与本设计的 rqlite 主备是两回事，一体机场景不使用。）

### 3.6 `A2X_REGISTRY_HA_MEMBERS`

当前**非空即拒绝启动** —— `parse_runtime_config()` 见到非空值直接抛 `ValueError("… current build is single-node …")`。成员集的**奇偶校验（偶数自动去尾 + 告警）**同样未实现。

### 3.7 鉴权门控

`image/router.py`、`instance/router.py`、`/api/nodes/{node}/heartbeat` **三组路由均无 auth 依赖**。即使跑了 `a2x-registry auth init`，这些接口照样匿名可调。而 `A2X_REGISTRY_BIND` 在一体机部署里被设成业务网卡 IP，等于 LAN 内任何人都能注册 / 删除镜像和实例。

### 3.8 多机 rqlite 组集群的部署

`module.sh` 只做 `systemctl enable --now rqlited`，吃 rqlite rpm 的**默认配置（单节点、HTTP 与 Raft 都在 loopback）**。多机需要生成 rqlited 配置：Raft 绑业务网卡（`-raft-addr <网卡IP>:4002`）、各节点互相 `-join`。同时缺 **4002 的防火墙白名单**与 **rqlite 节点间 TLS**（设计文档 §3.3.4 的安全要求）。

### 3.9 客户端 SDK 一体机接口封装

`client/a2x_registry_client/` 中没有 `/api/images`、`/api/instances`、`/api/nodes` 的任何方法。gateway 与镜像处理模块目前只能自行拼 HTTP 请求。

### 3.10 镜像仓文件删除

`ImageService._delete_repo_image()` 是 **stub**：未配 `A2X_REGISTRY_REPO_BASE` 时只打一条 warning 返回 `False`；即使配了也只打一条 "not implemented" 的 info。注销镜像**只删注册表条目，不删镜像仓文件**，响应里的 `repo_deleted` 恒为 `false`。

### 3.11 `lease-config` 不持久化

`POST /api/lease-config` 改的是内存里的 `NodeLeaseConfig` dataclass，进程重启回默认值。

## 4. 实现与契约的差异

代码行为与 [`registry_openapi.yaml`](./registry_openapi.yaml) 不完全一致的地方：

| # | 位置 | 差异 |
|---|------|------|
| 1 | `POST /api/images` 响应 | 实现多返回 `is_default` 字段；yaml 的 `ImageOpResponse` 无此字段 |
| 2 | `DELETE /api/images/{framework}/{version}` 响应 | 实现多返回 `repo_deleted`（恒为 `false`，见 [§3.10](#310-镜像仓文件删除)）；yaml 无此字段 |
| 3 | **存储后端默认值不一致** | `backend/__main__.py` 里 `A2X_REGISTRY_DB_KIND` 空值默认 `sqlite`，但真正建连接的 `backend/startup.py:_resolve_db_config()` 空值默认 **`memory`**。不设该环境变量时实际跑的是内存库，**进程退出数据全丢**。agent-os 部署显式设了 `rqlite`，故一体机不受影响；本地起服务容易踩 |
| 4 | `ImageSpec` / `Port` schema | yaml 中已标注"不再使用"，`runtime_spec` 改为不透明对象透传；保留仅为对照阅读 |
| 5 | 仓内 README | `README_forAgentTeam.md` / `README_forDistributed.md` 仍写 `a2x-registry --host 0.0.0.0`，但 CLI 已移除 `--host`，监听地址改由 `A2X_REGISTRY_BIND` 决定 |

## 5. 已知风险

### 5.1 多注册中心实例并存会互删数据

心跳租约在进程内存、不入库，且无主备逻辑（[§3.3](#33-注册中心主备跟随-rqlite-raft-选主)）。**打开心跳后**，多机形态下多个注册中心实例连同一份 rqlite，每个都跑自己的 sweeper；备实例租约表为空，会认定所有 node 超宽限，删掉主刚写进 rqlite 的实例条目。心跳关闭时不触发（扫描线程空转），但状态派生也随之失效。

**在主备实现之前，多机形态不可用** —— 只能单节点部署一个注册中心实例（当前 `agent-gateway` 模块的行为正是如此）。

### 5.2 4003 无鉴权且绑业务网卡

见 [§3.7](#37-鉴权门控)。只能靠外部防火墙限制来源 IP。
